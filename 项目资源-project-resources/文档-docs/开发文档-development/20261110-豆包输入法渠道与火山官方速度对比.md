# 20261110-豆包输入法渠道与火山官方速度对比

## 结论

本轮固定音频测试中，火山官方更早返回文字；短句定稿也更快，长句这次定稿反而更慢。不能据此断言某个渠道在所有场景都更快。

- 短句首次返回文字：火山官方早 157 ms；录音结束后的定稿等待短 173 ms。
- 长句首次返回文字：火山官方早 241 ms；定稿等待长 378 ms。长句每个渠道仅 1 次，结论只作参考。
- 8 次识别全部成功，忽略排版空格后，最终文字与预期完全一致；未发现首尾漏字。

## 范围与计时方法

对比 VoiceKey 内的两个渠道：当前已经优化的“豆包输入法”渠道，与新增的官方豆包语音 2.0。未测试独立豆包输入法应用的屏幕输入速度，也未测键盘上屏耗时。

两边使用同一份测试程序、同一音频和同一计时函数，避免把之前计时不同的结果直接比较：

1. WAV 解码在计时前完成，按每 20 ms 的绝对时刻模拟采集。
2. 采集开始即计时，并调用各渠道原有的预热入口；豆包输入法渠道会准备连接，官方付费渠道仍沿用不预建会话的实现。
3. 两边均等待 300 ms 再启动识别，匹配项目的右 Option 长按触发阈值；识别参数与当前安装版一致。
4. 首次返回文字：采集开始到首次非空识别回调。
5. 定稿等待：最后一帧采集结束到识别函数返回最终结果。
6. 短句约 4.49 秒，每个渠道各 3 次，使用中位数；长句约 11.73 秒，每个渠道各 1 次。
7. 单次启动新测试进程，交替顺序见下表。豆包设备缓存单独复制，火山密钥只由原生程序从本机钥匙串读取。

这测量的是当前客户端处理与云端响应的合计时间，不能单独归因于模型速度。网络、服务端负载、语句内容和长度都可能影响结果。
